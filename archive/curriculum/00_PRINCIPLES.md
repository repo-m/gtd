# The Curriculum: Operating System (OS)

This document defines the governance and execution logic for your lifelong intellectual scaling. It is designed to bridge the gap between high-level automotive engineering (SDV) and foundational humanistic wisdom.

---

## I. Mission & Theoretical Foundations

### 1. Primary Objective
To achieve a radical transition into **Software Defined Vehicle (SDV)** engineering while simultaneously constructing a robust metaphysical and ethical "Reality Engine."

### 2. The Humboldtian Pillar (*Bildung*)
True education requires the **active synthesis** of knowledge. Reading is the input; the "Humboldtian Artifact" is the verified output. You do not learn by consuming; you learn by creating.

### 3. The Dewey Pillar (Pragmatism)
Knowledge must be **anchored in the environment**. Theory is only valuable when it solves a living problem. The curriculum is a library to be "pulled" into reality, not a static list to be "pushed."

---

## II. The Execution Engine (Agile/Scrum)

### 1. Dual-Track Processing
*   **Track A: The Deep Forge (Major):** High-load engineering, logic, and math. Requires "Deep Work" blocks. (e.g., K&R C, Spivak, Tanenbaum).
*   **Track B: The Existential Lab (Minor):** Aesthetic recovery and existential inquiry. (e.g., Dostoevsky, Quran, Rumi).

### 2. The Weekly Sprint Loop
Every Sunday, you perform a **Sprint Review** in `02_SPRINTS.md`:
1.  Log progress on Track A and B.
2.  Submit artifacts to the `artifacts/` folder.
3.  Trigger the **AI Scrum Master** to analyze context and propose the next sprint's "Pull."

---

## III. Governance Rules (Constraints)

### Rule #1: The Humboldtian Artifact ("Definition of Done")
A book is only marked as "Done" when a verified artifact is published to `/artifacts`:
*   **Technical:** Code repository, re-derivation, or system design.
*   **Humanist:** 1,500-word synthesis essay or conceptual translation.

### Rule #2: The Pragmatic "Context Pull"
If a real-world problem at work (SDV latency, team conflict) emerges, you may bypass the priority list to pull a relevant book (e.g., *Kleppmann* or *Luhmann*) forward.

### Rule #3: The Rule of 50 (Sunk Cost Protection)
If a book is a "soul-crushing slog" after 50 pages, drop it. Your "mental hardware" isn't ready for that "software" yet. Return it to the backlog.

### Rule #4: The Anti-Burnout Constraint
Never run two Track A books in parallel. Use Track B as a "passive recovery" mechanism to prevent cognitive fatigue.
